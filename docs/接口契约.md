# 接口契约（V1.0）

> 本文档是前后端唯一契约来源。任何字段变更先改本文档，再改代码。
> 后端：`api/src/modules/<module>/router.ts`；前端：`web/src/views/<module>/`。

## 一、通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `http://127.0.0.1:8081/api` |
| 鉴权 | `Authorization: Bearer <JWT>`，登录后 12 小时有效 |
| 请求体 | `application/json; charset=utf-8` |
| 成功响应 | `{ "code": 0, "message": "ok", "data": {...}, "meta": { "total": 64, "page": 1, "pageSize": 10 } }` |
| 失败响应 | `{ "code": 401, "message": "用户名或密码错误" }`，HTTP 状态码与 `code` 一致 |
| 分页参数 | `page`（默认 1）、`pageSize`（默认 10，最大 100），分页接口必返 `meta` |
| 时间格式 | `YYYY-MM-DD HH:mm:ss`；日期字段 `YYYY-MM-DD` |
| 权限错误 | 401 未登录 / 403 无模块权限；前端统一提示 |
| 审计 | 所有认证用户的写操作由后端中间件自动写入 `audit_log`（操作日志） |
| 数据级权限 | 角色 `data_scope`：`ALL` 全量、`DEPT` 本部门、`SELF` 仅本人；列表接口后端已按范围过滤 |

### 模块权限码

`dashboard`、`asset`、`compliance`、`risk`、`rbac`、`audit`、`ops`，每模块分 `read` / `write`。
写接口在路由上使用 `requirePerm('<code>', 'write')`，读接口使用 `requirePerm('<code>')`；**除 `/auth/*` 与 `/health` 外所有接口都必须先 `authenticate`**。

## 二、通用接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查：mysql/redis 状态、资产数、运行时长 |
| GET | `/meta` | 平台元信息：模块清单、权限位、数据范围枚举 |
| POST | `/auth/login` | 登录，body `{username,password}`；返回 `token`、`user`、`menus`、`unreadCount`；失败 5 次锁定 30 分钟 |
| GET | `/auth/profile` | 当前用户 + 菜单树 + 未读通知数 |
| POST | `/auth/logout` | 注销 |
| PUT | `/auth/password` | 修改密码 `{oldPassword,newPassword}`，策略：≥10 位且含大小写+数字+特殊字符 |
| GET | `/auth/notifications` | 站内通知（个人 + 全员公告，最近 20 条） |
| PUT | `/auth/notifications/:id/read` | 通知已读 |
| GET | `/dashboard/overview` | 看板总览（见下方字段） |

## 三、数据资产治理（module: asset）

路径前缀 `/assets`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/assets/stats` | read | 统计：总量/敏感资产/分级分布/分类 TOP/来源系统/状态分布/平均质量分 |
| GET | `/assets/categories` | read | 分类树 + 每类资产数 + 每级（公开/内部/机密/绝密）数量 |
| GET | `/assets` | read | 分页列表；筛选 `keyword`（名称/编号）、`level`、`status`、`categoryId`、`deptId`、`stage`、`sort`（`size_gb`/`sensitivity_score`/`last_access_at`，可 `-` 前缀倒序） |
| GET | `/assets/:id` | read | 详情：资产字段 + `tags[]` + `lifecycle[]` + `riskCount` + `checkCount` |
| POST | `/assets` | write | 新建，必填 `asset_name/category_id/dept_id/source_system/data_type/data_level/owner` |
| PUT | `/assets/:id` | write | 更新资产（含分级、状态、责任人） |
| PUT | `/assets/:id/level` | write | 调整分级 `{data_level, reason}`，写 `asset_lifecycle` |
| POST | `/assets/:id/scan` | write | 单资产扫描复核：重算敏感度分并写生命周期记录，返回 `{sensitivity_score, findings[]}` |
| POST | `/assets/scan` | write | 全局扫描任务（演示近似：模拟扫描来源系统），返回 `{taskId, scanned, newAssets, changed, durationMs}` |
| GET | `/assets/:id/lifecycle` | read | 生命周期轨迹列表 |
| GET | `/assets/tags` | read | 标签云（标签名 + 资产数） |
| GET | `/assets/export` | read | 导出 CSV（响应 `text/csv`，文件名 `数据资产台账_YYYYMMDD.csv`） |

字段枚举：`data_level` 公开/内部/机密/绝密；`data_type` 结构化/半结构化/非结构化；`status` 正常/待治理/风险/已归档；`lifecycle_stage` 采集/存储/使用/共享/销毁。

## 四、安全合规管理（module: compliance）

路径前缀 `/compliance`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/compliance/overview` | read | 规则总数、最近批次通过率、整改闭环率、待审批共享数、脱敏规则数、风险分类分布 |
| GET | `/compliance/rules` | read | 分页；筛选 `keyword`、`basis`、`category`、`status` |
| POST | `/compliance/rules` | write | 新建规则 |
| PUT | `/compliance/rules/:id` | write | 更新规则（含启停） |
| GET | `/compliance/checks` | read | 分页检查结果；筛选 `batchNo`、`result`、`ruleId`；返回 `rule_title/rule_code/basis` |
| POST | `/compliance/checks/run` | write | 执行检查（演示近似）：抽样规则生成新批次，返回 `{batchNo, total, passed, warning, failed, durationMs}` |
| GET | `/compliance/checks/:id` | read | 检查详情（含规则原文、证据、耗时、同批次对比） |
| GET | `/compliance/batches` | read | 批次列表 `{batch_no, checked_at, total, passed, failed, warning, rate}` |
| GET | `/compliance/rectify` | read | 分页整改单；筛选 `status`、`keyword`；返回 `rule_title`、`overdue`（布尔） |
| PUT | `/compliance/rectify/:id` | write | 更新整改 `{status, progress, measure}`；闭环时写 `closed_at` |
| GET | `/compliance/masking` | read | 脱敏规则列表；筛选 `algorithm`、`mask_type` |
| POST | `/compliance/masking/:id/test` | write | 试脱敏 `{sample}`，返回 `{before, after, algorithm}` |
| PUT | `/compliance/masking/:id` | write | 更新脱敏规则（启停/算法） |
| GET | `/compliance/approvals` | read | 共享审批分页；筛选 `status`、`keyword`；返回 `asset_name/receiver/purpose/risk_level` |
| POST | `/compliance/approvals` | write | 提交共享申请 `{asset_id, receiver, purpose, share_way}` |
| PUT | `/compliance/approvals/:id/approve` | write | 审批 `{approved: boolean, comment}`；通过时写 `approver/approved_at` |
| GET | `/compliance/report` | read | 合规报告：`batchNo` 可选，返回 `{batchNo, generatedAt, summary{cards}, byCategory[], byBasis[], fails[], rectify[]}` |

## 五、智能风险监测（module: risk）

路径前缀 `/risk`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/risk/overview` | read | 待处置/紧急数、今日事件、规则命中 TOP5、24 小时趋势、事件类型分布 |
| GET | `/risk/rules` | read | 监测规则列表（含 `hit_count`、`enabled`） |
| PUT | `/risk/rules/:id/toggle` | write | 启停规则 `{enabled}` |
| GET | `/risk/events` | read | 分页；筛选 `level`、`status`、`eventType`、`keyword`、`start`、`end`；返回 `asset_name`、`rule_name` |
| GET | `/risk/events/:id` | read | 详情 + `related`（同 IP/同账号最近 5 条事件）+ `asset` |
| POST | `/risk/events/:id/handle` | write | 处置 `{status: 处置中|已处置, note}`，写 `handled_by/handled_at` |
| POST | `/risk/events/:id/ignore` | write | 忽略 `{note}` |
| GET | `/risk/trace?eventId=` | read | 溯源链路：`{event, account, asset, auditLogs[], sameIp[]}`（演示近似：按 IP/账号关联审计日志） |
| GET | `/risk/trend?days=7` | read | 趋势 `{date, low, mid, high, urgent}` |
| GET | `/risk/realtime` | read | 实时监控：最近 20 条事件 + 每分钟计数 + 重点 IP TOP5 |

## 六、权限安全管控（module: rbac）

路径前缀 `/rbac`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/rbac/overview` | read | 用户数/启用数/角色数/部门数/近 7 天登录失败数/锁定账号数 |
| GET | `/rbac/users` | read | 分页；筛选 `keyword`、`deptId`、`status`、`roleCode`；返回 `roles[]`、`last_login_at` |

| PUT | `/rbac/users/:id` | write | 更新用户（不含密码） |
| PUT | `/rbac/users/:id/status` | write | 启停/解锁 `{status: 0|1}` |
| POST | `/rbac/users/:id/reset-password` | write | 重置密码 `{password}`，需符合密码策略 |
| GET | `/rbac/roles` | read | 角色列表 + `userCount` + 权限位矩阵（模块 × r/w） |

| GET | `/rbac/menus` | read | 全量菜单树（含权限码与可见性） |
| GET | `/rbac/apis` | read | 接口权限清单 + 各角色授权矩阵 |
| GET | `/rbac/depts` | read | 部门列表（含负责人、用户数、资产数） |
| GET | `/rbac/policy` | read | 安全策略：密码长度/有效期/失败锁定/会话/IP 白名单（读 `sys_config`） |
| PUT | `/rbac/policy` | write | 保存安全策略 `{items:[{key,value}]}` |

路径前缀 `/audit`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/audit/overview` | read | 今日日志量/失败率/类型分布/近 7 天趋势/活跃用户 TOP5/异常 IP TOP5 |
| GET | `/audit/logs` | read | 分页；筛选 `logType`、`result`、`keyword`（用户/动作/IP）、`start`、`end`；按时间倒序 |

| GET | `/audit/export` | read | 导出 CSV（同筛选条件，最多 5000 条） |
| GET | `/audit/integrity` | read | 不可篡改校验：`{total, verifiedAt, chainValid, checked, broken[]}`（演示近似：对日志行做 SHA-256 链式校验） |

| POST | `/audit/reports` | write | 生成报表 `{reportType: 日报|周报|月报|年报}`，按统计写入 `total_events/risk_events/compliance_rate/content` |
| GET | `/audit/reports/:id` | read | 报表详情（含摘要正文） |
