# 演示脚本（3–5 分钟）

> 版本：V1.0.0　演示角色：admin（超级管理员）　总时长：约 4 分钟（8 步）　前置：按 [部署运行.md](部署运行.md) 启动并通过 [验收清单.md](验收清单.md) 第一、二章。
> 讲解口径：先讲"为什么"再讲"怎么做"；每步只点 1–2 个关键数字，其余留给提问。
> 覆盖操作：资产分级、合规检查、风险处置、权限调整、审计校验、运维工单六类，均基于同一套演示数据。

## 一、演示前 60 秒准备

| 检查 | 命令/动作 | 通过标准 |
| --- | --- | --- |
| 数据重置 | `npm run db:reset` | 末行 `RESULT=PASS`（演示前必做，清掉联调残留） |
| 数据校验 | `npm run db:validate` | `RESULT=PASS passed=69 failed=0` |
| 服务就绪 | 访问 `http://127.0.0.1:8081/api/health` | `status`、`mysql`、`redis` 均为 UP |
| 浏览器 | Chrome/Edge 打开 `http://127.0.0.1:5174`，窗口 1440×900 | 登录页正常，无控制台报错 |
| 账号 | admin / Admin@2026 | 可登录 |

## 二、演示步骤

| 步 | 时长 | 操作 | 预期现象 | 讲解要点 |
| --- | --- | --- | --- | --- |
| 1 | 30s | 打开 `http://127.0.0.1:5174` → 输入 admin / Admin@2026 → 登录 | 进入"平台总览"，右上角显示"超级管理员"，左侧 7 个顶级菜单 | 统一身份认证：JWT 12 小时、密码策略、连续 5 次失败锁定 30 分钟 |
| 2 | 40s | 停留看板：指资产总数、敏感资产、未闭环风险、待处理工单、合规通过率 | 数字为 64 / 33 / 9 / 9 / 70%；四级分级与风险等级图有数据；最近风险事件按等级排序 | 一屏看清"资产—合规—风险—运维"四本账；数据来自 27 张表的实时聚合，缓存 20 秒 |
| 3 | 40s | 左侧"数据资产治理" → "台账" → 按分级筛"绝密" → 打开一条资产详情 | 列表显示 13 条绝密资产；详情含标签、生命周期轨迹、敏感度分 | 分级分类是治理起点：公开/内部/机密/绝密四级，调级会写生命周期留痕 |
| 4 | 40s | "安全合规管理" → "合规检查" → 点"执行检查" → 选最近批次查看结果 | 生成新批次（如 CHK-2026-006），结果分通过/警告/不通过，通过率约 70% | 规则依据《数据安全法》《个人信息保护法》《等保 2.0》与行业规范；不通过项进入整改池 |
| 5 | 35s | "智能风险监测" → "风险事件" → 打开一条"紧急"事件 → 点"处置" → 填写处置说明并提交 | 事件状态变为"已处置"，列表与看板未闭环数随之减少（看板最多滞后 20 秒） | 五类异常：越权访问、批量导出、异常登录、数据篡改、敏感外传；处置全程留痕 |
| 6 | 40s | "权限安全管控" → "角色" → 选中"审计员" → 查看/调整某模块的读权限并保存 → 退出重登 auditor 验证 | 保存成功提示；auditor 重新登录后仅见授权的只读菜单，写操作返回 403 | RBAC 四级：用户-角色-菜单/按钮-接口；数据范围 ALL/DEPT/SELF 再叠加一层隔离 |
| 7 | 30s | "安全审计追溯" → "审计日志" → 按类型"操作日志"筛选 → 打开一条详情 → 点"完整性校验" | 日志含操作人、IP、结果；校验返回"链完整"，算法 SHA-256 | 四类日志全量留痕；哈希链校验为演示级近似，用于表达"不可篡改"的校验思路 |
| 8 | 30s | "服务保障运维" → "运维工单" → 新建一张"变更申请"工单 → 受理 → 处理 → 验证 → 关闭 | 工单状态四态流转，轨迹逐条记录操作人与时间；监控页 CPU/内存/QPS 有 24h 趋势 | 工单闭环 + 监控告警 + 定时备份 + 配置/版本管理，构成服务保障闭环 |

**收尾（20s）**：回到看板刷新一次，口述"工单新增 1 张、审计日志新增若干条，其余基线不变"；说明演示数据可在 1 分钟内重建（`npm run db:reset`）。

## 三、演示注意事项

| 场景 | 处理 |
| --- | --- |
| 看板数字未立即变化 | 看板缓存 20 秒，等待或刷新；不要连续狂点 |
| 权限调整后当前会话未变化 | 权限在登录时装载，需退出重登（演示中正好体现"重新认证"） |
| 演示中误操作产生数据 | 演示结束后 `npm run db:reset` 恢复基线 |
| 接口 502 / 页面白屏 | 检查 `npm run dev` 两个进程是否存活；`curl http://127.0.0.1:8081/api/health` |
| 登录被锁定 | 等待 30 分钟，或由 admin 在用户管理重置；演示前避免连续输错密码 |
| 截图需求 | 另开窗口执行 `npm run screenshots`，产物在 `docs/screenshots/` |

## 四、提问应答要点

| 问题 | 回答 |
| --- | --- |
| 数据是真的扫描出来的吗？ | 资产扫描、监控采集、备份、脱敏为**演示级近似**（见 [DECISIONS.md](DECISIONS.md) D-012），流程与数据闭环真实，底层不接外部扫描器/备份系统 |
| 能否对接真实环境？ | 契约与表结构已抽象，替换扫描器/采集器即可；K8s、多租户、SIEM 明确不在本期（D-015） |
| 性能与可用率？ | 看板缓存 20 秒、列表走索引；未做并发压测，不承诺 99.9%（PLAN-MATRIX H-01/H-02） |
| 日志真的不可篡改吗？ | 演示版用 SHA-256 链式校验表达校验机制，生产需接 WORM 存储或区块链存证 |
