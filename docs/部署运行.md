# 部署运行手册

> 适用版本：V1.0.0（软著演示版）　平台：Windows 10/11 + PowerShell 7（pwsh）　最后更新：2026-11-07
> 目标：在一台干净的开发机上，按本手册从零拉起 MySQL / Redis / API / Web，重建演示数据，并跑通五道门禁。

## 一、环境要求

| 组件 | 要求 | 本项目实际使用 | 说明 |
| --- | --- | --- | --- |
| 操作系统 | Windows 10/11 x64 | Windows | 亦可在 macOS/Linux 运行，仅路径写法不同 |
| Node.js | ≥ 20（LTS） | v24.22.0 | `node -v` 校验；npm 随 Node 安装（实测 11.19.1） |
| npm | ≥ 10 | 11.19.1 | 使用 npm workspaces（`api`、`web`） |
| Docker Desktop | 支持 `docker compose` | 运行中 | 仅用于 MySQL 8.0 与 Redis 7；Docker CLI 需在 PATH 或在脚本候选路径中 |
| 浏览器 | Chrome / Edge 最新版 | Chromium（Playwright） | E2E 与截图使用 Playwright 自带 Chromium |
| 端口 | 8081、5174、13306、16379 空闲 | 同上 | 冲突处理见第六章 |

> 演示数据不需要手工导入：`api/db/init.mjs` 会建表并重放种子；每次重放后的记录数见 [STATUS.md](STATUS.md) 的计数基线。

## 二、首次安装与启动

```powershell
# 1) 进入项目根目录
cd D:\MyCodes\data-security-platform

# 2) 安装依赖（npm workspaces，一次装两个子包）
npm install

# 3) 启动容器依赖（MySQL 13306 / Redis 16379）
npm run docker:up

# 4) 建表 + 重放演示数据
npm run db:init

# 5) 校验数据基线（69 项断言）
npm run db:validate

# 6) 一键起前后端（API 8081 + Web 5174，自动等待就绪）
npm run dev
```

`npm run setup` 等价于第 2～5 步的组合（依赖 → 容器 → 建库 → 校验），首次部署推荐直接使用。

### 分开启动（推荐用于排查）

```powershell
# 终端 A：API（tsx watch，改代码自动重启）
npm run api

# 终端 B：Web（Vite 开发服务器）
npm run web
```

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| Web | http://127.0.0.1:5174 | 前端页面，`/api` 由 Vite 代理到 8081 |
| API | http://127.0.0.1:8081/api | 所有接口前缀 `/api` |
| 健康检查 | http://127.0.0.1:8081/api/health | 无需登录，返回 MySQL/Redis 状态与资产数 |
| MySQL | 127.0.0.1:13306 | 库 `datasec`，用户 `datasec` / `DataSec_2026` |
| Redis | 127.0.0.1:16379 | 密码 `DataSec_2026` |

## 三、容器与数据管理

```powershell
npm run docker:up      # 启动 MySQL + Redis（首次会拉镜像）
npm run docker:down    # 停止容器（保留数据卷）
node scripts/docker.mjs status   # 查看容器状态
node scripts/docker.mjs logs     # 查看容器日志
```

- 数据卷：`datasec-mysql-data`、`datasec-redis-data`；`docker:down` 不删卷，数据保留。
- 重置演示数据：`npm run db:reset`（等价 `node api/db/init.mjs`，会 DROP 27 表后重建并重放种子）。
- 重新校验：`npm run db:validate`，末行应为 `RESULT=PASS passed=69 failed=0`。
- 注意：**门禁与演示前必须 `db:reset`**，避免接口联调留下的工单/备份/日志使计数断言失败。

## 四、验证命令（五道门禁）

```powershell
npm run build        # API tsc --noEmit + Web vue-tsc/vite build
npm run test:api     # 接口门禁（需 API 已启动、数据已重置）
npm run test:e2e     # E2E 门禁（Playwright，需 Web+API 已启动）
npm run db:validate  # 数据契约门禁
npm run check:docs   # 文档门禁
npm run verify       # 依次跑全部门禁（可加 --skip-e2e / --skip-docker）
```

| 门禁 | 通过标准 |
| --- | --- |
| build | 退出码 0；API 无 TS 错误；Web `vue-tsc` 无错误且 `vite build` 成功 |
| test:api | 末行 `RESULT=PASS`，全部用例 PASS，无 5xx |
| test:e2e | 末行 `RESULT=PASS`，无 console 错误、无横向滚动 |
| db:validate | 末行 `RESULT=PASS passed=69 failed=0` |
| check:docs | 末行 `RESULT=PASS passed=N failed=0` |

自动化脚本（可选）：

```powershell
npm run screenshots   # 生成 docs/screenshots/ 下的交付截图（需 Web+API 已启动）
```

## 五、常见问题（FAQ）

### Q1. PowerShell 执行 npm 报"无法加载文件……因为在此系统上禁止运行脚本"

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

或改用 `pwsh -Command "npm run dev"`。公司策略限制时，用 `cmd /c "npm run dev"` 绕过。

### Q2. PowerShell 里提示"无法将 docker 项识别为 cmdlet"

Docker Desktop 已安装但 CLI 未进 PATH。三种处理任选：

1. 在 Docker Desktop 设置中把 `resources\bin` 加入 PATH 后重开终端；
2. 临时指定路径：`$env:DOCKER_PATH = 'D:\DevTools\Docker\resources\bin\docker.exe'`；
3. 本项目 `scripts/docker.mjs` 已内置候选路径（`D:\DevTools\Docker\resources\bin\docker.exe`、`C:\Program Files\Docker\Docker\resources\bin\docker.exe`），直接 `npm run docker:up` 即可。

验证：`docker version` 或 `node scripts/docker.mjs status`。

### Q3. 端口被占用（8081 / 5174 / 13306 / 16379）

```powershell
netstat -ano | findstr ":8081"
taskkill /PID <PID> /F
```

- 8081 被占：改 `api/.env` 的 `PORT`，同时改 `web/vite.config.ts` 代理目标（需重启 Vite）。
- 5174 被占：Vite `strictPort` 会直接报错，关闭占用进程即可。
- 13306/16379 被占：改 `docker-compose.yml` 端口映射与 `api/.env` 对应项（改完需 `docker compose up -d` 重建容器）。

### Q4. 中文乱码 / 脚本输出乱码

- 终端编码：`chcp 65001` 切换 UTF-8；推荐使用 Windows Terminal + PowerShell 7。
- 文件编码：本仓库源码与文档均为 UTF-8（无 BOM）；用记事本另存时勿选 ANSI/GBK。
- 用 PowerShell 读取 `.mjs` 出现乱码多为终端解码问题，不代表文件损坏；用 VS Code 打开确认。
- 数据库连接串已指定 `utf8mb4`，写入中文无需额外设置。

### Q5. `npm run dev` 起来了但页面 401 / 白屏

1. 确认 API 8081 已就绪：`curl http://127.0.0.1:8081/api/health`。
2. 浏览器清掉旧令牌：开发者工具 → Application → Local Storage 删除 `datasec_token`、`datasec_user`，重新登录。
3. 确认登录账号未被锁定：连续 5 次密码错误会锁定 30 分钟，可等待或用 admin 重置。

### Q6. `db:validate` 失败（如"运维工单数量为 22"）

通常是联调写入了新记录。执行 `npm run db:reset` 后重跑；仍失败则查看失败行的实际值，对照 [STATUS.md](STATUS.md) 基线表定位。

## 六、停止与清理

```powershell
# 停止前后端：在对应终端 Ctrl+C
npm run docker:down            # 停容器（保留数据卷）
docker compose down -v         # 停容器并删数据卷（下次需重新 db:init）
```

> 演示交付前建议执行一次：`npm run db:reset` → `npm run db:validate` → 启动前后端 → 截图/演示，保证数据与文档基线一致。
